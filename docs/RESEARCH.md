# Демо графика и рабочая учетная система

Исследование официальной документации: 25 сентября 2026 года.

## Выбранный подход

Для небольшого демо одного листа используем обычную HTML-таблицу и JavaScript. Так проще точно повторить блоки дней, объединенные итоги смен и цвета ролей, сохранив небольшой размер приложения. Это наш выбор для текущего объема, а не ограничение готовых библиотек.

Интерфейс можно использовать в обеих версиях, заменив слой авторизации и хранения:

| | Демо на GitHub Pages | Рабочая версия на хостинге клиента |
|---|---|---|
| Интерфейс | HTML, CSS, JavaScript | Тот же интерфейс |
| Вход | Демонстрационный `admin/admin` | Проверка пароля сервером, PHP-сессия |
| Данные | Пример и локальное сохранение в браузере | Общая база данных через PHP API |
| Права и расчеты | Показывают предполагаемое поведение | Проверяются и выполняются сервером |
| Совместная работа | Нет общего состояния между пользователями | Проверка версий записей и конфликтов правок |

[GitHub Pages публикует статические файлы и не выполняет PHP](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site). Поэтому вход в демо не защищает данные, включенные в публичные JS/JSON-файлы. Демо не является готовой серверной учетной системой. Исходную книгу и реальные персональные данные публиковать вместе с демо не требуется.

## Рассмотренные решения

| Решение | Что дает | Ограничения и вывод |
|---|---|---|
| **Jspreadsheet CE** | MIT; редактирование как в таблице, копирование диапазонов, выпадающие списки, объединения ячеек | Подходит для обеих площадок. В CE нет полноценной группировки строк/колонок, межлистовых расчетов и автоматического изменения ссылок формул при копировании. Хороший кандидат при расширении табличных функций. |
| **Tabulator** | MIT; редакторы и списки, фильтры, группировка, закрепление колонок, spreadsheet mode | Подходит для обеих площадок. Удобен для структурированного учета; произвольные объединения диапазонов как в Excel не найдены в проверенной документации. |
| **Handsontable** | Развитое редактирование диапазонов, объединения, списки, copy/paste | Работает в браузере на обеих площадках. Для коммерческого рабочего использования нужна платная лицензия; бесплатная evaluation-лицензия не заменяет ее. Для бюджетного проекта не выбран. |
| **Univer** | Открытое ядро Apache-2.0; редактор с формулами, объединениями и проверкой данных | Сам браузерный редактор размещается статически. Совместное редактирование и серверная конвертация требуют отдельных серверных модулей и лицензирования; актуальный Server SDK использует Node.js, поэтому не подходит для самостоятельного запуска на указанном PHP-only тарифе. |
| **Dolibarr** | Готовая ERP/CRM на PHP с установкой через браузер и загрузку файлов без SSH | Может работать на shared hosting с подходящими PHP и БД, но не на Pages. Для повторения конкретного листа потребуется собственный модуль; для небольшого демо избыточен. |

## Рабочая версия на PHP

Предлагаем PHP API и MySQL/MariaDB, доступную через PDO. **Наличие БД, расширения `pdo_mysql`, поддерживаемой версии PHP и HTTPS нужно проверить у хостинга:** пока известна только возможность запускать PHP. [PDO MySQL](https://www.php.net/pdo-mysql) предоставляет доступ к базе; [PHP-сессии](https://www.php.net/manual/en/session.examples.basic.php) и [API хеширования паролей](https://www.php.net/manual/en/ref.password.php) подходят для серверного входа.

Минимальная модель данных: пользователи, роли и разрешения, бригады, сотрудники, записи графика, выплаты, тарифы и журнал изменений. Это проектное предложение; окончательные сущности зависят от согласованных правил учета.

- Пароли хранить через `password_hash`, проверять через `password_verify`; использовать серверные сессии и защищенные cookie. Демо-пароль не переносить в рабочую установку.
- На каждом запросе проверять права пользователя, входные значения и допустимость операции. Запросы к БД выполнять с параметрами; изменяющие запросы защищать от CSRF.
- Расчеты и денежные итоги повторно вычислять сервером. **Тарифы и формулы оплаты пока неоднозначны:** значения и расчеты демо служат иллюстрацией и требуют согласования перед рабочим запуском.
- Для сохранения использовать транзакции и номер версии записи. Если другой пользователь уже изменил запись, вернуть конфликт и предложить обновить данные, а не молча перезаписать их.
- Хранить автора, время и содержание изменений; предусмотреть резервное копирование и восстановление базы. Для первого этапа достаточно обновления данных по запросу или короткого опроса API, без постоянного WebSocket-сервера.

## Развертывание без терминала сервера

1. Проверить возможности тарифа, создать базу и пользователя через панель хостинга.
2. Подготовить и проверить файлы локально. Если появятся Composer/npm-зависимости, установить и собрать их локально; загружать уже готовый комплект.
3. Загрузить HTML/CSS/JS/PHP через файловый менеджер панели или FTP/SFTP, доступный у провайдера. Конфигурацию с реквизитами БД хранить вне публичного каталога либо закрыть от прямой выдачи.
4. Импортировать SQL-схему через phpMyAdmin или другой инструмент панели. Создать администратора через одноразовую защищенную процедуру настройки и отключить ее после установки.
5. Проверить вход, права разных ролей, сохранение, расчет итогов, конфликт двух одновременных правок и восстановление резервной копии.

Таким образом, GitHub Pages используется для показа интерфейса, а PHP-хостинг — для настоящего многопользовательского учета. Переход не требует другого внешнего вида, но требует отдельной реализации и проверки серверной части.
